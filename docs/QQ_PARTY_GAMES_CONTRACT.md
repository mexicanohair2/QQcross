# QQCross Party Games — контракт интеграции

**Игры:** Team Word и QQ Draw  
**Клиенты:** отдельные статические GitHub Pages-приложения  
**Общий backend:** существующий Supabase-проект QQCross  
**Версия контракта:** 19 ноября 2026

## 1. Принципы

- Не создавать отдельные аккаунты, таблицы профилей, друзей или отдельный сервис авторизации.
- Использовать `auth.users` и `public.profiles` основного QQCross.
- Сетевой участник — только подтверждённый, неанонимный пользователь Supabase Auth с существующим профилем.
- Идентификатор, ник и аватар берутся из `auth.uid()` и `public.profiles`. Переданные клиентом ник и состояние комнаты не считаются доверенными.
- Секретные ответы и варианты слов хранятся в серверных таблицах и никогда не попадают в общий снимок до разрешённого раскрытия.
- Локальные боты не создают записи в `qq_party_players` и не вызывают сетевые RPC.

GitHub Pages приложения имеют разные origins. Браузер не разделяет между ними localStorage-сессию Supabase; пользователь отдельно выполняет вход в каждое приложение, используя ту же учётную запись QQCross. Новый аккаунт при этом не создаётся.

## 2. Общие таблицы

| Таблица | Назначение |
|---|---|
| `public.qq_party_rooms` | Комната, код, игра, ведущий, статус, номер раунда, публичное состояние и срок жизни |
| `public.qq_party_players` | Реальные участники, серверные user_id, ник, аватар и место |
| `public.qq_party_secrets` | Закрытый ответ активного раунда |
| `public.qq_party_events` | Общая история событий комнаты |
| `private.qq_party_word_bank` | Закрытый словарь, из которого сервер выбирает ответы |
| `private.qq_party_draw_choices` | Три приватных варианта слова для текущего художника |
| `public.qq_party_draw_events` | Упорядоченные события холста, без передачи целого изображения |

В комнату можно добавить от 2 до 32 реальных пользователей. На таблицах Party включён RLS. Клиенты не получают прямого права записи в серверные секреты и события холста. Таблица словаря и варианты QQ Draw находятся в схеме `private` без клиентских политик чтения.

## 3. Общие RPC

Все перечисленные клиентские RPC вызываются с Supabase access token текущего пользователя.

| RPC | Назначение |
|---|---|
| `qq_party_create_room(p_game, p_nickname, p_player_limit, p_public_state)` | Создать комнату `team_word` или `crocodile` |
| `qq_party_join_room(p_code, p_nickname)` | Войти по шестизначному коду |
| `qq_party_get_room(p_room_id)` | Получить публичный снимок и только разрешённую текущему участнику приватную часть |
| `qq_party_leave_room(p_room_id)` | Покинуть комнату |
| `qq_party_is_member(p_room_id)` | Проверка членства для политик доступа |

Параметры ника в create/join оставлены для совместимости клиента, но сервер использует значение профиля QQCross. Состояние комнаты, переданное при создании, не используется как авторитетное состояние игры.

## 4. Team Word

### Запуск

`qq_party_start_team_word(p_room_id, p_words, p_length)`

Сервер проверяет ведущего, игру, число участников и состояние комнаты. Ответ выбирается случайно из `private.qq_party_word_bank`. Клиентские `p_words` и `p_length` не определяют ответ.

### Попытка

`qq_party_team_guess(p_room_id, p_word)`

Любой участник комнаты может отправить догадку без ожидания персонального хода. Сервер проверяет членство, активность раунда, длину, русский алфавит, повторы и лимит истории. В общую историю добавляются серверный профиль отправителя и оценка букв.

### Таймер и публичное состояние

`qq_party_tick_team_word(p_room_id)` использует серверное время и отметку `started_at`. Каждые 15 секунд сервер открывает одну случайную закрытую позицию. Клиент может запрашивать обновление, но не управляет временем. Секрет остаётся недоступным до завершения раунда.

## 5. QQ Draw

### Выбор художника и слова

`qq_party_start_crocodile(p_room_id, p_word)` запускает первый раунд. Сервер выбирает художника случайно среди реальных участников и выдаёт ему три слова через приватную часть `qq_party_get_room`.

`qq_party_refresh_croc_choices(p_room_id)` выдаёт художнику новые варианты. `qq_party_confirm_croc_word(p_room_id, p_word)` подтверждает только одно из серверных предложений. Пока слово не подтверждено, остальные участники видят лишь статус выбора.

### Попытки и передача роли

`qq_party_croc_guess(p_room_id, p_word)` доступен всем участникам, кроме художника. При верной догадке сервер фиксирует решение и победителя. `qq_party_next_croc_round(p_room_id, p_word)` доступен победителю; сервер назначает его художником следующего раунда.

### Протокол холста

Каждый обычный штрих передаётся через `qq_party_add_stroke(p_room_id, p_stroke)`. Объект события содержит:

- `roundId` — идентификатор комнаты и раунда;
- `playerId` — id текущего пользователя;
- `type` — `begin`, `move` или `end`;
- `sequence` — непрерывный порядковый номер;
- `strokeId` — идентификатор штриха;
- `x`, `y` — нормализованные координаты от 0 до 1;
- `color` — HEX-цвет;
- `thickness` — толщина от 1 до 32.

Сервер проверяет членство, текущий раунд, право художника, тип события, цвет, диапазоны координат, начало и завершение штриха, последовательность и дублирование. Повтор уже принятого события с тем же содержимым идемпотентен.

Дополнительные RPC:
- `qq_party_clear_canvas(p_room_id)` — добавить серверное событие очистки;
- `qq_party_undo_canvas(p_room_id, p_stroke_id)` — добавить событие отмены;
- `qq_party_get_draw_events(p_room_id, p_after_sequence)` — восстановить историю порциями до 1000 событий.

Клиент подписывается через Supabase Realtime на `qq_party_rooms`, `qq_party_players`, `qq_party_events` и `qq_party_draw_events`. События холста дополнительно читаются курсором, поэтому переподключение не требует передачи изображения.

## 7. Проверки и границы подтверждения

- Unit-тесты клиентов запускаются GitHub Actions через `npm test`; команда включает `node --check app.js`.
- Серверные миграции применены к Supabase и сохранены в `QQCross/supabase/migrations`.
- Состояние базы проверено запросами к функциям, таблицам, ограничениям, Realtime publication и Supabase advisors.
- Проверка двух реальных устройств требует двух подтверждённых пользовательских сессий; до такой проверки нельзя утверждать, что фактическая многопользовательская сессия уже прошла end-to-end тест.
- При текущей реализации вход в комнаты — по коду. Отдельный диалог приглашения конкретного друга поверх существующего списка друзей QQCross ещё не реализован.
